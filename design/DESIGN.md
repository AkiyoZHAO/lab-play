# lab-play 设计系统规范

> 这是 lab-play 这个「个人空间」的视觉语言基座。它约束的不是某一个页面，而是**所有玩法、所有面板必须共享的美学**。任何新增内容都必须长在这套语言里，不得各自发明风格——这是「重 UI」定位下最重要的一条纪律。
>
> UI 是**可换的薄表层**（见〔十一〕）：接口（anchor）固定，皮肤可换。但无论哪套皮肤，都从同一份 token 取值、遵守同一套基调。

唯一的取值来源是 [`design/tokens.css`](tokens.css)。本文档解释这些 token 背后的意图和使用规则。

---

## 一、基调

**中性色 · light · 简约雅致。**

- **少即是多**：优先用留白、层级、排版解决问题，而不是靠颜色和装饰。
- **克制的色彩**：全站以中性灰阶为主体，强调色只在关键动作/焦点处点缀，绝不铺大面积。
- **雅致的动效**：过渡慢而柔（240–420ms + 柔和缓动），微妙而非炫技。宁可没有动效，也不要浮夸的弹跳/闪烁。
- **精致的排版**：清晰的字号层级、舒适的行高、恰当的字距。标题可用衬线（`--font-serif`）营造气质，正文用无衬线。

参考心智：像一本装帧考究的书、一个安静的展厅，而不是一个花哨的游戏厅。

---

## 二、用色规则

| 场景 | 用什么 | 不要 |
|---|---|---|
| 页面/卡片底色 | `--c-bg` / `--c-surface` / `--c-surface-alt` | 用强调色做大块背景 |
| 正文/标题 | `--c-text` | 用纯黑 `#000` |
| 次要说明 | `--c-text-muted` / `--c-text-faint` | 用低对比度到看不清 |
| 分隔线/描边 | `--c-line` / `--c-line-strong` | 用重阴影替代描边 |
| 关键动作（主按钮、当前焦点、选中态） | `--c-accent` / `--c-accent-soft` | 一个界面里出现多个"抢眼点" |
| 完成/正向反馈 | `--c-positive` | 大红大绿的高饱和色 |
| 跳过/负向反馈 | `--c-negative` | 同上 |

**一个界面只应有一个视觉焦点。** 强调色是稀缺资源。

---

## 三、排版层级

- 主菜单大标题：`--fs-2xl` + `--font-serif` + `--ls-tight`
- 区块标题：`--fs-xl` / `--fs-lg`
- 正文：`--fs-base` + `--lh-base`
- 说明/元信息：`--fs-sm` / `--fs-xs` + `--c-text-muted`
- 小标签（tag/pill）：`--fs-xs` + `--ls-wide`（宽字距显克制）

---

## 四、间距与形状

- 间距一律取 `--sp-*` 刻度（8px 基准），不写任意像素值。
- 慷慨使用留白：区块之间用 `--sp-7`/`--sp-8`，大留白用 `--sp-9`。
- 圆角：小元素 `--radius-sm/md`，卡片 `--radius-lg`，大面板/入口 `--radius-xl`，胶囊 `--radius-full`。
- 阴影极轻，light 风格靠「描边 + 微阴影」而非重投影。

---

## 五、动效

- 时长用 `--dur-*`，缓动用 `--ease-out`（进入/浮现）或 `--ease-inout`（状态切换）。
- 悬停/焦点变化要柔和（透明度、轻微位移、描边变化），避免缩放弹跳。
- 已内置 `prefers-reduced-motion` 支持，写动效时不必重复处理。

---

## 六、游戏感的表达方式

lab-play 是个游戏系统，需要「游戏感」——但游戏感和「简约雅致」并不冲突，关键在于**用什么手段做**。这里立一条硬规则：

**游戏感靠层级、材质、仪式来做，不靠高饱和霓虹。**

参照心智：塔罗牌、高品质桌游卡背——克制而有仪式感，不是廉价手游 gacha 的闪光粒子。

- **深浅层级**：稀有度、重要度这类"分级"信息，一律在中性墨色里做深浅（见 `--rar-*` 色阶），越稀有底色越深、描边越考究，绝不引入蓝/紫/金的俗套稀有度配色。
- **材质描边**：卡牌/牌背用考究的描边 + 极轻内阴影 + 一两根「金属感强调线」（`--rar-*-glow`）营造质感，而不是靠彩色或厚重投影。
- **开牌仪式**：随机/揭晓类交互做成"翻牌"而非文字滚动——先展示带纹样的卡背，再翻转露出结果。3D flip 要克制（一次翻转、慢而柔），不做轮播滚动、不做连续闪烁。
- **矢量纹样**：所有图形用 inline SVG（零外部资源、随主题色、零构建），几何抽象纹样而非具象图标或表情包；稀有度越高纹样越考究。

> 判断标准：游戏感应该像"翻开一张装帧考究的牌"，而不是"点亮一个霓虹按钮"。

---

## 七、新页面（玩法 / 面板）的视觉一致性约束（硬性）

任何新增的玩法 / 面板必须满足：

1. **只引入 `design/tokens.css`**，所有颜色/间距/字号/圆角/动效从 token 取，禁止写死。
2. **不引入新的字体、新的强调色、新的圆角体系**——需要新 token 时，先加进 `tokens.css`（全站共享），而不是在局部硬编码。
3. **遵守"一个界面一个焦点"**：主动作用强调色，其余保持中性。
4. **保持留白与克制**：不堆砌装饰、不加与整体气质冲突的插画/表情包/高饱和色块。
5. **动效遵循雅致原则**：慢而柔，服务于反馈而非表演。

> 判断标准：把新页面的截图和首页并排放，应该一眼看出「是同一个网站」。做不到就是跑偏了。

---

## 八、图表（Dashboard / 聚合面板）

聚合面板是把事件变成「证据」，不是花哨仪表盘。图表服务于数字，而不是反过来。

- **数字是主角**：KPI 用衬线大号；柱/条只是它的注解，不要填满、不要图例爆炸。
- **配色克制**：只用中性阶 + `--c-positive`（完成）/ `--c-negative`（跳过）。进行中用 `--c-line-strong`。不引入第三种强调色，不用高饱和色块。
- **零依赖**：图表用 CSS 柱/条实现，不引第三方图表库（保持零构建）。
- **空也要雅致**：没数据的日子留一根中性底线，不要空白塌陷，也不要画 0 的假柱。

---

## 九、世界层 / 首页（薄 UI 层）

首页是这个个人空间的「门面 / 客厅」，不是信息面板。它是一层**薄 UI**，核心就是几个入口，可随时换。

- **简约舒适、留白克制。** 第一版用最简单的设计——现有 light 卡片语言即可，不堆场景、不堆信息。
- **允许一点个性 whimsy。** 可以放一两个有性格的小元素（如一个小月历图标、手绘矢量纹样），但**整体不搞复杂 UI**。
- **零外部资源。** 首页也守 inline SVG / CSS，不引图片 / gif（守住零构建与手工克制）。
- **它只是摆放 anchor 的一种皮肤**（见〔十一〕）。沉浸式场景（庭院式，把入口编进画面）是**未来可能的一套皮肤，不是默认**；真要做，也在世界层这一层做，内部功能页不受影响。

> 首页与「高信息密度」是分工关系：密度全部丢给 Dashboard（〔十〕），首页保持薄和静。

---

## 十、Dashboard（高信息密度）

总览 Dashboard 是一个面板，承担「一眼看全貌」，走 **startpage 式 widget 网格**。

- **widget 网格组织密度**：月历、最近时间线、各面板 readiness、统计条……用小部件拼贴，而不是一条长信息流。
- **仍是 token 驱动、克制**：高密度 ≠ 花哨。数字为主角，颜色只用中性阶 + `--c-positive` / `--c-negative`，不引第三种强调色。
- **零依赖图表**：CSS 柱 / 条实现，不引图表库。空数据也要雅致（见〔八〕）。
- 视觉纪律与〔八〕图表一致；Dashboard 是它的容器与扩展。

---

## 十一、UI 可换：anchor 与皮肤

「系统优先、UI 是薄表层」在视觉上的落实：

- **anchor（接口）固定**：每层有哪些入口 / 互动是固定的（清单见项目书〔五〕）。
- **皮肤只决定呈现**：一套皮肤 = 把每个 anchor 绑到「一个视觉元素 + 位置 + 过场」，加上一组从 `tokens.css` 取值的主题。极简皮肤把 `panel:career` 绑成一张卡；庭院皮肤可能绑成一盏灯笼——**同一个 anchor，不同摆位**。
- **默认兜底是硬要求**：皮肤必须为未显式摆位的 anchor 提供兜底位置，否则每加一个玩法 / 面板都要手改皮肤。
- **架构留白，不做玩具**：当前不做「一键换肤」功能；只是让 UI 层可整套替换。真要多套皮肤时，皮肤之间共享 token 基调，内部功能页始终保持干净结构。

> 可换的主要是**首页那层薄 UI**。内部功能页（玩法 / 面板）跟随皮肤的 token，但结构不随皮肤大改。

---

## 十二、演进方式

- 设计语言的任何调整都改 `tokens.css` 一处，全站生效——这是把「重 UI」做得可持续的关键。
- 需要新组件模式（如卡牌、进度条、成就徽章、Dashboard widget）时，先在这里补一节「组件意图」，说明它的视觉规则，再落地到具体页面。
